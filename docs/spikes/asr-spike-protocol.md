# 語音辨識 spike：測試步驟

對象：在實機上跑 `ASRSpike` 的大人（Michael 與家中另一位大人）。**門檻與決策表要在開測前由 Michael 簽核**，跑完才不會事後找理由。

## 本輪範圍（D19）

目前只有一支 iPhone 17 Pro Max（iOS 27），沒有 iOS 17 或 18 的裝置，所以**本輪不定最低 iOS 版本**。本輪只回答：
1. 在 iOS 27 上，路徑 A、B、C 哪一條達標。
2. 路徑 A、B 在飛航模式下能不能辨識（能否離線）。
3. 退路實際多常觸發、孩子會看到什麼。

最低 iOS 版本等有 iOS 17／18 的裝置再補測一輪。

## 開測前檢查

- [ ] 房間裡沒有孩子；這支 App 不交給孩子用。「旁人說話」「孩子說法」兩格只能用大人模仿，或用另一台裝置播合成語音；不得用孩子本人或孩子的錄音。
- [ ] 設定 → 隱私權與安全性 → 分析與改進：關閉「分享 iPhone 分析」。**全程關閉，不設打開的對照輪。**
- [ ] 設定 → Siri：關閉「改進 Siri 與聽寫」。**全程關閉，不設打開的對照輪。**
- [ ] 同一週內測完（免費個人開發者帳號裝的 App 7 天後失效）。
- [ ] Team ID 只寫在 `app/Local.xcconfig`，不要在 Xcode 專案設定裡填（會套到 KidsAI）。
- [ ] 記下裝置資訊：機型、iOS 版本、系統語言、地區、Siri 語言、聽寫語言、可用空間（App「可用性」區塊有部分資訊）。

## 門檻（簽核後不改）

在「安靜30cm」、停頓 2.5 秒、出聲門檻 -45 dB、有播提示、**飛航模式**的條件下計算：

| 指標 | 門檻 | 看哪條路徑 |
|---|---|---|
| 跟讀算完成（關鍵詞或出聲） | ≥ 95% | A、B、C |
| 關鍵詞命中 | ≥ 80% | A、B |
| 關鍵詞誤觸發（每一種負例各自計算） | ≤ 5% | A、B |
| 出聲誤觸發（只看「沒聲音」「只播提示」，各自計算） | ≤ 5% | C（A、B 也適用，因為有出聲就算完成） |
| 開始收音（提示播完到收到第一段音訊）p90 | ≤ 300 ms | 全部 |
| 講完後出現鼓勵 p50／p90 | ≤ 停頓秒數 + 300 ms | 全部 |

另外照實報告，不設門檻：「還在說就被鼓勵」的比例、撞上限的比例、電視聲與旁人說話的出聲誤觸發（已知限制）。

## 決策表（本輪只用來選路徑，不定最低 iOS）

| 結果 | 建議 |
|---|---|
| A 或 B 在飛航模式下達標 | 正式 App 採用達標的路徑；兩條都達標時，以權限需求較少、延遲較短者為準 |
| 只有 C 達標 | v1 只判斷有沒有出聲，不做語音辨識；不需要語音辨識權限 |
| A、B、C 都不達標（包括 C 的出聲誤觸發不達標） | 另案調整出聲門檻或互動方式，本輪不定案 |
| 語音辨識權限視窗附加了 Apple 的說明（與「只在這支 iPhone 上處理」矛盾） | 偏向改用只需要麥克風權限的路徑 |

## 測試順序

1. **全新安裝**後先測路徑 B，再測 C，最後才測 A。A 會要求語音辨識權限；先測 B、C 才看得出它們是否只需要麥克風權限。
2. 分塊進行：每一塊（同一組設定）做完，就到「彙總」抄數字，再進下一塊。執行按鈕上方的大字會顯示目前設定，確認後再按。跑錯就按「刪除上一筆」。
3. App 會自動把每條路徑的第一次標成「冷啟動」。

## 測試矩陣

- **句子**：App 內 6 句（單元 1–4 的跟讀句）。
- **環境**：安靜30cm、平放1m、電視聲（1–2 m 外）、旁人說話。
- **說話者**：成年女性、成年男性，各念 5 次。其中一人可刻意帶台灣口音（說→ㄙㄨㄛ、查→ㄘㄚ、ㄣ／ㄥ不分）。
- **說話內容**：
  - 跟讀：照句子念。
  - 孩子說法：小聲、句中停頓 1.5 秒、邊笑邊說、說太快、只說半句（只描述，不進決策）。
  - 搶先說：提示還在播就開口（量提示與開麥時序的衝突）。
  - 負例：沒聲音、只播提示（要打開「先播提示語音」、不說話）、說別的話（例如「我不要」）。
- **負例次數（D28）**：「沒聲音」「只播提示」每條路徑各 60 次；「說別的話」各環境 10 次，只看點估計。
- **參數比較**（只在安靜30cm、跟讀）：停頓 1.2／1.8 秒各一輪；總長上限 8 秒一輪；出聲門檻 -50／-40 dB 各一輪；「只播提示」負例另用「回音消除」模式跑一輪。
- **網路**：主要數字一律在飛航模式下蒐集（打開 iPhone 飛航模式，並在 App 勾「飛航模式中」）；有網路那輪只做對照。

每條路徑 × 條件約 60 次，95% 信賴區間約 ±10 個百分點，只夠判斷可不可行。

## 系統狀態（每種記錄落到哪條退路、錯誤代碼）

- 麥克風權限：拒絕。註：「螢幕使用時間」造成的限制在 App 裡也會顯示成拒絕，無法區分。
- 語音辨識權限：拒絕、受限制（分開記）。
- Siri／聽寫關閉；聽寫語言沒有中文（台灣）；系統語言英文。
- 路徑 B 的模型：未安裝 → 按「下載 zh-TW 模型（spike 限定，會連網）」並確認（D21(b)，唯一的網路例外）→ 已安裝有網路 → 已安裝＋飛航模式。記下下載時間。
- 測試中來電、切換到藍牙耳機（App 會記成「中斷」）。
- 權限跳窗：記下 iOS 在語音辨識權限視窗裡有沒有附加 Apple 的說明（只寫文字描述，不截圖）。

## 測完

1. 在「彙總」把每組數字抄到 `asr-spike-report.md`（只抄數字、比例與錯誤代碼）。
2. 用 Xcode → Window → Devices and Simulators 下載 ASRSpike 的 App container，列出 `.caf`、`.wav`、`.m4a` 等音檔，並搜尋 6 句的關鍵詞。`Library/Caches` 若有框架留下的檔案，只記「有／無」與檔案類型，不打開內容。**若發現音檔或辨識文字，該輪數字作廢**，並立刻刪除 Mac 上下載的 container。
3. 不要看、也不要存 Xcode 主控台的輸出。
4. 當天刪除 ASRSpike（權限也會一併清掉）。

## 禁止

逐字稿、截圖、螢幕錄影、Console 或 log 匯出、自由筆記裡寫下「它把某句聽成什麼」，都不得進 repo，也不得貼給外部模型。報告只放次數、比例、延遲、可用與否、錯誤代碼。

## 已知限制

- 大人的結果是上限；孩子的聲音、停頓與環境都不同，辨識率會更低。
- 「只播提示」用的是系統合成語音；正式 App 會用預錄配音，音量與尾音不同。
- 提示語是「跟我一起說」，但提示播完、再隔 300 毫秒才開麥；跟著提示一起說的孩子，句首可能收不到（「搶先說」這一格就是在量這件事）。
